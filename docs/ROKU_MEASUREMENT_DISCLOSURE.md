## 1. Platform and measurement methodology

**Overview.** We operate our own impression measurement infrastructure on
Cloudflare's edge — not a third-party measurement vendor. The system has two
functions:

1. **Impression measurement** — count and attribute CTV ad impressions fired by
   Roku's Advertising Framework (RAF).
2. **Call-conversion attribution** — match inbound phone calls (driven by a
   unique tracking number per creative) back to impressions, and report
   conversions to Roku's Conversions API (CAPI).

**End-to-end methodology.**

```
1. Impression
   Roku device (RAF) fires our HTTPS impression pixel (1x1 GIF).
   - URL is HMAC-signed by us (campaign|creative|expiry) to prevent spoofing.
   - RAF substitutes Roku macros: RIDA, LMT, APPID, CACHEBUSTER.

2. Edge ingestion (Cloudflare Worker)
   - Validate parameters + verify HMAC signature + check campaign allowlist.
   - Honor LMT: if lmt=1 or RIDA is zeroed, the identifier is discarded.
   - Deduplicate per device/creative within a configurable window.
   - Record:
       (a) aggregate event to Analytics Engine (RIDA hashed), and
       (b) a short-lived matching record (raw IP/RIDA) for call attribution.
   - Return the pixel immediately; processing is asynchronous.

3. Call attribution (probabilistic)
   - In-house PBX posts a signed webhook on a QUALIFIED call (duration >= N).
   - Dialed number (DNIS) -> creative (1 tracking number per creative).
   - Match the call to the best-guess in-window impression for that creative,
     scored by time proximity + coarse caller-area-code geo. A confidence
     score (0-1) accompanies every match.
   - We have ONLY the caller's phone number (no device ID from the call), so
     this match is PROBABILISTIC, not deterministic.

4. Conversion reporting (Roku CAPI)
   - Fire a server-to-server conversion to Roku with the best-guess impression
     IP/RIDA + hashed caller phone + coarse geo + confidence score.
   - If no impression is in-window, fall back to hashed-phone-only so the
     conversion is still reported.
```

**Sampling note.** Real-time aggregate counts use Cloudflare Analytics Engine,
which applies statistical sampling; totals are computed with the per-row
`_sample_interval` weight. High-precision data is available from the raw
short-retention tier. We are **not** MRC/IAB-accredited and do not perform
accredited invalid-traffic (GIVT/SIVT) filtration beyond input validation,
signature verification, and deduplication.

## 2. Data collected / identifiers

### Received on the impression pixel
| Field | Source | Type |
|-------|--------|------|
| `advertiser_id`, `campaign_id`, `creative_id` | Set by us (signed) | Non-personal |
| `app_id` | Roku `APPID` macro | Non-personal (channel/app) |
| `ifa` (RIDA) | Roku `RIDA` macro | Personal data (advertising ID) |
| `lmt` | Roku `LMT` macro | Consent/opt-out signal |
| `cachebuster` | Roku `CACHEBUSTER` macro | Non-personal |
| Device IP | Network (Cloudflare `CF-Connecting-IP`) | Personal data |
| Coarse geo (country/region/city) | Cloudflare edge from IP | Derived geo. Postal code is deliberately **not** collected (DPP §5 sensitive-data) |
| Timestamp | Server-generated | Non-personal |

### Generated by us
| Field | Description |
|-------|-------------|
| Salted SHA-256 hash of RIDA | Used for dedup/reach in stored analytics |
| Deduplication key | `hash(ifaHash\|campaign\|creative)` per window |
| Conversion `event_id` | Deterministic `call_{callId}_{creativeId}` for Roku 10-min dedup |
| Match confidence score | 0–1 probabilistic attribution confidence |

### Received from the in-house PBX (qualified calls only)
| Field | Type |
|-------|------|
| Caller number (ANI) | Personal data — **hashed (SHA-256), never stored raw** |
| Dialed tracking number (DNIS) | Maps to creative |
| Call start time, duration | Non-personal |
| Optional sale value / currency | Non-personal |

**Identifiers sent to Roku via CAPI:** matched impression IP address and RIDA
(both omitted when LMT is set), SHA-256-hashed caller phone, and coarse geo
(state/zip).

## 3. Data usage

Collected data is used solely for advertising **measurement, attribution,
reporting, and optimization** of the advertiser's own campaigns:

- **Measurement** — count impressions per campaign/creative/app/geo.
- **Attribution** — probabilistically match qualified inbound phone calls to the
  impression that likely drove them.
- **Reporting** — aggregate dashboards and trends (impressions, reach estimates,
  geo distribution, conversions).
- **Optimization** — feed conversions back to Roku CAPI so Roku can optimize
  delivery toward call-converting audiences.

We do **not** use the data for: building cross-advertiser profiles, resale,
audience brokering, retargeting outside the advertiser's own campaigns, or any
purpose unrelated to the campaigns generating the data.

## 4. Data retention

| Tier | Contents | Retention |
|------|----------|-----------|
| Call-matching store (Durable Object) | **Raw** IP + RIDA + geo (attribution only) | ~60 minutes (attribution window), then auto-purged |
| Analytics Engine (real-time) | **Hashed** RIDA + dimensions | 3 months (platform-fixed) |
| R2 raw tier | **Hashed** RIDA + dimensions | 30 days |
| R2 aggregated tier | **No identifiers** — hour/dimension rollups only | 13 months |

Raw device IP is **never** persisted in analytics/reporting tiers (reduced to
geo). Raw RIDA and raw IP exist **only** in the ~60-minute matching store. Raw
caller phone numbers are never stored (hashed in-flight). Identifier-level data
is not retained long-term; only de-identified aggregates persist beyond 30 days.

## 5. Data disclosure (sharing with third parties outside Roku)

**No personal data is shared with any third party outside of Roku.**

- Conversion data (IP, RIDA, hashed phone, coarse geo) is transmitted **only to
  Roku** via the Conversions API, server-to-server, for the measurement/
  attribution/optimization purposes above.
- Infrastructure is operated by us on **Cloudflare** (Workers, Analytics Engine,
  R2) acting as our hosting **sub-processor** under contract — not an independent
  recipient that uses the data for its own purposes.
- The in-house PBX is our own system (caller phone is hashed before any external
  transmission).
- No data brokers, no ad networks other than Roku, no resale, no audience
  syndication.

> If an advertiser later engages an additional sub-processor (e.g. a CRM for
> sale confirmation), it would be disclosed and contractually bound; none is in
> use for this integration today.

---

## 6. Tag ownership

**Proprietary, first-party owned pixels — no third-party pixels.**

- The **impression tag** is our own 1×1 GIF endpoint served from our Cloudflare
  Worker (`/pixel`). It is a single, direct, **unwrapped** HTTPS GET fired
  client-side by RAF (per Roku certification), HMAC-signed by us. It does not
  redirect to, wrap, or load any third-party pixel.
- The **conversion** is reported via Roku's own CAPI from our server. There is
  no third-party conversion pixel.
- We do not embed, piggyback, or daisy-chain any external measurement/ad-tech
  tags.
